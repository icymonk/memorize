# 수학 문제 생성·공유 계획

> 상태: 초안 · v0.1 · 리뷰 후 [features/math.md](../features/math.md) v1.1과 개발 문서에 반영

세 가지로 수학 문제를 만들고 함께 푼다.

1. **변형 문제 템플릿**: 내가 정한 포맷에서 숫자만 바뀐다.
2. **단원별 생성**: 교육과정 학년·단원을 고르면 문제를 만들어 준다.
3. **공유·서로 풀기**: 문제집을 공개하고, 서로 풀고, 통계를 본다.

## 1. 변형 문제 템플릿 (MATH-14) — "포맷은 내가, 숫자는 자동"

### 1-1. 만드는 화면
| 칸 | 예시 | 설명 |
| --- | --- | --- |
| 지문 | `사과가 {a}개 있고 {b}개를 더 샀어요. 모두 몇 개일까요?` / `$\frac{{a}}{{b}} + \frac{{c}}{{d}}$` | `{변수}` 자리에 숫자가 들어감. 수식도 사용 가능 |
| 변수 | `a`: 정수 10~99 · `b`: 정수 1~9, 0 제외 | 종류: 정수 / 소수(자릿수) / 분수 / 목록에서 고르기(이름·단위·물건) |
| 계산값 | `s = a + b`, `g = gcd(a, b)`, `x = (c - b) / a` | 변수로 계산한 값. 지문·정답·해설에 쓸 수 있음 |
| 조건 | `a > b`, `(c - b) % a == 0`, `s <= 100` | 조건을 만족할 때까지 숫자를 다시 뽑음 (예: 방정식 답이 정수로 떨어지게) |
| 정답 | 숫자 `{s}` (허용 오차), 분수는 약분된 값으로 비교 | 1/2 = 0.5 같은 동치는 명세대로 인정 |
| 객관식 오답 | `{s+1}`, `{s-10}`, `{a*b}` | 흔한 실수를 식으로 적음. 겹치면 자동으로 다른 값으로 바꿈 |
| 힌트·해설 | `{a} + {b}를 세로셈으로 해 보세요` | 변수 사용 가능 |

- **미리보기**: "다른 숫자로" 버튼을 누르면 샘플 5개가 나온다. 조건이 너무 빡빡해 숫자를 못 뽑으면 실패율을 경고하고 저장을 막는다.
- **빈칸 채우기 프리셋**: 아래 포맷을 고르면 변수·조건·정답이 미리 채워져 있어 숫자 범위만 고치면 된다.
  - 일차방정식 `ax + b = c`
  - 분수의 덧셈·뺄셈
  - 비와 비율
  - 직사각형·삼각형 넓이
  - 거리·속력·시간
  - 연립방정식

### 1-2. 풀 때
- 풀 때마다 숫자가 새로 나온다. "다시 풀기"나 오답 노트에서 다시 풀 때도 다른 숫자라서 답을 외워서는 못 푼다.
- 시험으로 낼 때는 설정에서 고른다. **응시자마다 다른 숫자**(MATH-17, 기본값, 커닝 방지)와 모두 같은 숫자 중 하나다.
- 통계는 숫자와 상관없이 템플릿 하나를 한 문제로 묶어서 낸다.

### 1-3. 정답 보안·정확성 (기술)
- 계산식·조건·오답 식은 **정답 문서(`questionKeys`)**에 둔다. 풀이자에게는 서버가 만든 완성 지문만 내려간다.
  - 정답 식이 클라이언트에 노출되지 않는다.
  - 문제 문서에는 목록용 샘플 1개만 둔다.
- 서버는 `seed`로 같은 숫자를 다시 만들어 채점한다. `seed`는 응시·풀이 기록에 저장한다.
  - 풀기: 서버가 문제를 내려줄 때 seed를 정하고, `checkAnswer`가 같은 seed로 채점한다.
  - 시험: `startAttempt`가 응시자마다 seed를 정해 시험지를 만든다. 채점은 기존 `finalize`가 맡는다.
- 계산기는 `shared/`에 한 벌만 둔다. 앱 미리보기와 서버 채점이 같은 코드를 쓴다.
  - `eval`은 쓰지 않는다. mathjs의 제한된 `evaluate`를 쓰고, 분수는 정확한 유리수 계산을 한다(0.1+0.2 오차 없음).
  - 난수는 결정적 PRNG(seed가 같으면 같은 숫자)를 쓴다.
  - 허용 함수: `+ - * / ^ % gcd lcm abs sqrt round floor ceil min max`.

## 2. 단원별 생성 (MATH-15, MATH-16) — "학년·단원 고르면 만들어 줌"

### 2-1. 교육과정 목록
- 2022 개정 교육과정 수학을 넣는다. 범위는 초1부터 고1(공통수학)까지이고, 학년 → 영역 → 단원 → 세부 개념 순서다.
- 전역 읽기 전용 데이터(`curricula`)로, 시드 JSON을 저장소에 커밋해 배포 때 넣는다.
- 목록에 없는 단원은 자유 입력한다(MATH-13 그대로). 자유 입력한 단원은 생성에는 안 나오고 분류·성취도에만 쓰인다.

### 2-2. 생성 화면
1. 학년 → 단원(→ 세부 개념)을 고른다.
2. 난이도(1~5), 개수(5/10/20), 정답 형식(숫자/객관식/섞기)을 정한다.
3. **미리보기 목록**에서 빼고 싶은 문제를 빼고, "숫자 다시"나 "이 문제 템플릿 수정"을 한다.
4. 새 문제집으로 저장하거나 기존 문제집에 추가한다. 저장되는 건 템플릿이라 풀 때마다 숫자가 바뀐다.

### 2-3. 문제 출처
| 출처 | 내용 | 장점 | 한계 |
| --- | --- | --- | --- |
| **A. 내장 템플릿 라이브러리** | 단원마다 우리가 만든 템플릿 5~15개: 연산, 분수·소수, 약수·배수, 비례식, 일차·연립·이차방정식, 좌표, 넓이·부피, 경우의 수·확률 기초 등 | 비용 0, 정답 100% 정확, 오프라인에서도 빠름 | 문장제·도형 그림·그래프 해석은 약함 |
| **B. 워크스페이스 템플릿** | 멤버가 만든 템플릿 중 단원이 붙은 것(공개 범위 안) | 우리 모임에 맞는 문제가 쌓임 | 처음엔 비어 있음 |
| **C. AI 초안 (선택)** | 단원·성취기준·난이도·예시를 주면 AI가 **템플릿 형태**(지문+변수+계산식)로 만들고, 우리 계산기가 정답을 계산·검증 | 문장제 등 다양한 문제 | 사용량 과금, 사람 검토 필요 |

- AI를 쓸 때도 **AI가 직접 계산한 정답은 쓰지 않는다**. AI는 식만 만들고 계산은 우리 엔진이 한다. 숫자를 뽑지 못하거나 정답이 정수가 아닌 템플릿처럼 검증에 실패하면 버린다.
- AI 호출은 서버 함수에서만 한다. 사람·워크스페이스별로 하루 생성 한도를 둔다. 키는 GitHub Secret → Secret Manager로 넣는다.

## 3. 공유하고 서로 풀기
| 기능 | 상태 | 내용 |
| --- | --- | --- |
| 문제집 공개 대상·편집 범위 | 명세 있음 (MATH-10) | 나만 / 지정한 사람 / 그룹 / 워크스페이스 |
| 풀기·즉시 채점·힌트·해설·풀이 메모 | 명세 있음 (MATH-20~23) | 한 문제씩 풀기 |
| 내 문제 풀기 = 연습 | 명세 있음 (MATH-24) | 통계에서 제외 |
| 작성자 통계 | 명세 있음 (MATH-43) | 문제별 정답률·힌트 사용률. 템플릿은 숫자 무관하게 합산 |
| 시험으로 내기 | 명세 있음 (MATH-25) | 이번에 만든 시험·미션 기능을 그대로 사용 + 응시자마다 다른 숫자 |
| 활동 피드 | 기존 기능 재사용 | "OO님이 '분수 덧셈 20제'를 공개했어요", "다 풀었어요" |
| 다른 워크스페이스로 복사 | 기존 문제 복사 재사용 | 템플릿째 복사 |
| 이의 신청 | 명세 있음 | 맞는데 오답 처리되면 출제자에게 알림 |
| 문제집 도전 기록 (추천 추가) | 새로 | 같은 문제집의 멤버별 정답률·걸린 시간 비교. 4단계 포인트·랭킹과 연결 |
| 워크스페이스 밖 공개 링크 | 후순위 | 지금 구조(멤버만 접근)와 달라서 나중에 따로 |

## 5. 개발 순서 (PR 하나씩)
| # | 내용 | 기능 ID |
| --- | --- | --- |
| M1 | 수식 표시(KaTeX)와 수식 입력(MathLive 화면 키보드, 휴대폰 지원) | MATH-01·02 |
| M2 | 문제집 + 수학 문제(숫자·객관식, 분수=소수 동치), 교육과정 목록 시드 + 자유 입력 | MATH-10~13 |

| M5 | 단원별 생성(내장 라이브러리 + 워크스페이스 템플릿) | MATH-15 |
| M6 | 시험으로 내기(응시자마다 다른 숫자), 오답 노트 연결 | MATH-25·17·42 |
| M7 | 단원별 성취도, 작성자 통계, 도전 기록 | MATH-40·43 |
| M8 | 연산 훈련(템플릿 엔진 재사용) | MATH-30~33 |

- 시작 전에 `math.md` v1.1(새 ID), `data-model.md`(템플릿 필드), `phase-plan`(순서)을 고치는 문서 PR을 먼저 올린다.
